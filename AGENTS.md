# Repository workflow

- The owner wants changes committed and pushed directly to `master`. Do not open pull requests unless explicitly requested.
- Keep dark page backgrounds pure black, but give buttons, search fields and other controls visibly tinted backgrounds.
- Preserve the centered floating player: maximum width 900px, translucent tinted background with backdrop blur, and 12px radii on all four corners.
- When lyrics are open, instantly hide the player with opacity 0 without an opacity transition. Keep its click target above the overlay to close lyrics, hide its controls from interaction, and switch the lyrics arrow with the open state. Use nonlinear easing for lyrics entry and exit.
- Android exception: when lyrics open, animate the player below the viewport with translateY and slide it back when lyrics close. Keep opacity visible during travel, disable interaction while lyrics are open, and calculate travel from the resting layout so custom CSS remains free to change bottom. Use the lyrics close button or system back to exit. Android must not render the custom scrollbar or apply desktop scrollbar styling; retain page scroll position restoration.
- Android draws edge-to-edge behind transparent system bars. Extend the navbar background through the top safe area, apply blur(10px), and inset its controls. Lyrics backgrounds cover the entire window without a separate status-bar strip. Read system night mode through the native bridge and update automatic appearance on configuration changes; respect manual appearance choices.
- Deduct system-bar space already reserved by vendor window layouts before applying web safe-area padding; do not add another 12px top gap. Android resolves every music track natively using the selected /song/url/v1 quality level, including background queues and resumption. Show actual source/format diagnostics in Settings only, never on the lyrics overlay. Huawei HarmonyOS 4.2 control-center integration requires vendor-specific confirmation; do not claim generic MediaSession guarantees admission into its supported-app list.
- Every push to `master` runs `.github/workflows/win64.yml` to build a Windows x64 NSIS Setup installer.
- The `win64` branch stores build artifacts only. Source changes belong on `master`.
- Use the existing `yarn.lock` for dependency installation. Build the Windows installer with `yarn electron:build-win64`.
- Settings support a persistent custom CSS URL, or a local file path/file:// URL in Electron. Apply user styles after built-in styles, reload local files on save, and allow clearing them to restore built-in styles.
- Verify the workflow result before reporting that an installer has been published.
- Android uses the local WebView UI with a native Media3/ExoPlayer MediaSessionService, not WebView audio. Preserve native background queues, audio focus, headset pause and session reconnection. Android API access is configured at first launch; do not hardcode an unverified third-party server.
- Android Settings has a persistent opt-in concurrent playback switch. When enabled, disable ExoPlayer automatic audio focus handling so this app can mix with other media apps; when disabled, restore ordinary focus handling. Apply changes to the live service and to background/resumed playback. Headset-disconnect pause remains enabled.
- Android song caching belongs in the native Media3 data-source chain, not WebView blob URLs. Preserve cache separation by track, requested quality, account and API configuration, with automatic writing, adjustable capacity, usage/complete/partial statistics and explicit clearing in Settings. Disabling automatic caching retains existing entries. Group settings by purpose and keep the linked modifier credit “由 kuanzzz.pages.dev 修改” alongside original author credit; do not restore the broken footer image.
- Android APKs are built by `.github/workflows/android.yml` and published to the `android` artifact branch. Keep the development signing certificate stable for installable updates; do not describe this certificate as an app-store signing key.

- Settings uses exactly four main sections: 播放、缓存、外观、其它. Do not restore the lyrics wall clock. Animate only route content with opacity/translateY, retaining cached pages and scroll restoration; navbar/player stay outside this transition and lyrics/player slide behavior stays independent. Place 主软件仓库 (qier222/YesPlayMusic) and 本构建仓库 (461c/YesPlayMusic) at the Settings footer with original-author/modifier attribution, never in the avatar menu.
- Android audio diagnostics use a track-checked native snapshot, refreshed on input-format and ready/tracks/playback events. Never replace a media queue item solely to publish diagnostics.

- Async route roots hidden by v-show must use v-page-reveal so entering after data arrives still fades/slides in. Images use v-image-fade for load/decode-driven opacity reveal, including cache hits and source changes; preserve lazy loading and respect reduced motion.

- Android may prefetch the user's playlist covers once. Never issue extra playlist/song API calls or enumerate full lists for artwork. Enroll song covers only from ordinary responses for library playlists/tracks, and persist them only on actual image requests. Random/recommended songs are not independently enrolled. Persist 224px list covers and on-demand 1024px artwork across launches, sharing photo identity across CDN shards/resize parameters, stop new downloads below 128MB free, and expose separate usage/clear controls under 缓存.

- Avatar/song context menus fade and translate vertically on entry/exit. Fade the thin navbar bottom divider in only when main.scrollTop > 1, and out at the top. Cover play buttons fade using opacity only and reset hover/touch focus on navigation or deactivation.

- ContextMenu styles must reach slotted items/header images through transitions. Use shared styles strictly namespaced under .context-menu (including ancestor dark mode), rather than scoped descendant rules that miss slots. Avatar menu is text-only. Clamp menus above the visible player and within viewport edges; scroll long menus internally.

- Artwork cache must share in-flight fetches (including prefetched covers), keep legacy cached entries usable, normalize existing resize query parameters, and expose hit/download/failure counters. Initialize known library membership before concurrent startup responses; do not add song/playlist API requests for caching.

- Persist library fields and ordinary playlist-detail responses in IndexedDB, scoped by account/API. Restore library data before refreshing; never gate the library page on network success. Offline/failed refreshes retain saved content. Switching accounts clears in-memory library state. Cached track/lyric/album reads must not start duplicate or unhandled refresh requests. Only metadata already requested during normal use is saved; never crawl playlists for offline support.

- Android must disable whole-WebView edge stretching with OVER_SCROLL_NEVER and prevent main's scroll chaining with overscroll-behavior: none. Fixed navbar/player must never scale or move with top/bottom boundary gestures; preserve normal scrolling and independent page/lyrics/player animations.

- Publish the optional Huawei compatibility APK with `-PhuaweiCompat=true` (`com.luna.music`, explicit YesPlayMusic label) alongside the ordinary package. Preserve original Java component names and signing certificate. Document the 汽水音乐 installation conflict and independent data; community package filtering workaround is not official vendor admission or proof of physical-device success.
